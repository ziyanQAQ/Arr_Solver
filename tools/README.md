# 帝江号排班求解器

Node.js 零运行时依赖的排班工具。默认就是**精确模式**：外层枚举时间轴、内层按类别做记忆化 DFS，
类别内同类设施**联合分配**，稳定班走闭式、衰减班逐日模拟。算法只负责算结果：
输出方案 + 搜索状态（跑完 / 预算耗尽 / 有候选不收敛 / 用了近似），不做任何最优性声明。

```bash
node tools/scheduler.mjs                       # 全干员满精英化
node tools/scheduler.mjs tools/roster.sample.json
node tools/scheduler.mjs --mfg=2干员
node tools/scheduler.mjs --assist
node tools/scheduler.mjs my.json --mfg=2干员 --grow=晶植:6,矿物:3
node tools/scheduler.mjs my.json --levels=center:3,mfg1:2,mfg2:2,grow:2,guest:1
node tools/scheduler.mjs --budget=200000 --time=5000
```

## 1. 输入

名单格式：

```json
{
  "operators": [
    { "name": "洛茜", "elite": 4 },
    { "name": "秋栗", "elite": 2 },
    { "name": "骏卫", "elite": 1 }
  ]
}
```

- `elite` 为精英化阶段 0–4，省略时按 4 处理；无效阶段、重复干员和 `data/ship-data.json` 里不存在的名字会报错。
- 技能档位取 `unlock ≤ elite` 的最高档（同一技能取最高档，不累加）。`unlock` 来自 `ship-data.json` 的 `shipSkills[].unlock`。
- 所有干员需在 `data/ship-data.json` 中有稳定的 `charId`，用于最终同分裁决。

## 2. 选项

| 选项 | 取值 | 默认 |
|---|---|---|
| `--mfg=` | `1干员1武器` / `2干员` / `2武器` | `1干员1武器` |
| `--grow=` | `晶植:n,菌类:n,矿物:n`；槽数之和不超培养舱容量 | 满级时 `晶植:9` |
| `--levels=` | `center:1..5,mfg1:1..3,mfg2:1..3,grow:0..3,guest:0..3` | 全设施最高等级 |
| `--priority=` | 四类别的一个排列 | 线索、干员经验、武器经验、培养 |
| `--assist` | 启用中枢助力（每天 2 点，按文档 §6.3-5 顺序顺延） | 关闭 |
| `--budget=` | 正安全整数，候选评价节点上限 | `2000000` |
| `--time=` | 正安全整数（毫秒），墙钟上限 | `30000` |
| `--data=` | 干员数据 JSON 路径（客户端 `TableCfg` 解析副本，含 `charId` 与帝江号技能） | `data/ship-data.json` |

省略 `--levels` 时使用满级配置。显式指定中枢等级后，省略的设施等级取该中枢可支持的最高等级。
配置校验等级解锁关系、工位数、培养位数、预算与优先级；非法输入在搜索前抛出。

## 3. 输出

| 段 | 内容 |
|---|---|
| 搜索 | 一行事实：中枢候选 `x/y`、节点数、逐日模拟次数；只有没跑完（预算耗尽 / 有不收敛候选 / 启用了近似）时才追加原因。跑完且无近似时只留计数，不做任何结论性声明 |
| 中枢 · 时间轴 | 换班时刻、两组名单、两段的 `u`/`v`、中枢自身 `C/R`，以及段长 > 13.889 h 的红脸空窗提示 |
| 类别汇总 | 四类别的等效小时/日与单位换算（线索＝张/信用，制造舱＝件，培养＝批/件，并按类别拆分） |
| 设施明细 | 每个设施的模式、换班、两组名单（含白板）、倍率；有助力时打印点数、轮转天数、注入时刻 |
| 心情闭环 | 每个班次的 `d`、`C`、`R`、`t满`、余量、稳定性 |
| 自检 | verifier 结论（人员唯一、人数合法、中枢约束、助力约束、产出可重算）——只校验合法性与重算，不判断最优性 |
| 缺口 | 排不出来而被记 0 的类别：原因（人手不足 / 排不出可行方案）与"可用几人、满工位需要几人" |
| 助力增量 | 开启助力时，与“同一求解器关掉助力”再跑一遍的四类别差值 |

## 5. 算法

```text
enumerateCenters(ops, cfg)                    外层层枚举时间轴
  ├ 中枢恢复干员 → 组(≤3 人) 两两配对 → (uA,uB) 等价归并 + 支配剪枝
  └ × h_中枢 1..23，中枢两段各自 R ≥ C 过滤

solveLayout
  └ for 每个中枢配置
      dfs(类别序号, 已占用, 剩余助力, 本深度前缀):
        · 每个类别单独求解：同一类别的多个设施**联合分配**（不是逐舱贪心）
        · 只保留「达到本类别最大值」的分支；同一占用集只留人数最少的一条
        · 值前缀剪枝：本深度前缀严格劣于现任 ⇒ 整棵剪掉（只剪浅层）
        · 记忆化键 = (类别序号, 完整占用集, 剩余助力)
```

要点：

1. **外层是中枢**：全船只有一条 `u(t)`，中枢配置在外层完整枚举（不做贪心升档）。
2. **类别内联合**：单类别的多个设施先用“占用集 ⊆ U 的最优值”做 subset-max（SOS）变换，再对 `U`
   求 `best(舱1,U) + best(舱2,R∖U)`，精确保证两组人不重叠——这是 `--mfg=2干员` 拿到 171.82 的前提。
3. **稳定走闭式**：`R ≥ C` ⇒ 每天心情回满、日循环重复 ⇒ 闭式 `E·min(h,1/d)` 即精确值（O(1)）。
4. **衰减才模拟**：按闭式/上界降序，上界低于已知最优即安全停；逐日模拟到收敛。
   收敛判据：①烧入后心情向量精确复现（取该循环均值）；②烧入后统计窗对半的两半均值相对差 ≤ `driftTol`。
   两条都不满足记作“不收敛”，该候选不能当真值用，最优性行会降级。
5. **助力**（`--assist`）：注入模型按会客室文档 §8.4——注入时刻取“目标心情降到 70%”那一刻，
   +30% 全额可用（不撞 100% 上限）。候选包含 1/2 点 × 目标轮转 × 受助班次，只在确有衰减班次时枚举；
   剩余点数随状态传给后续类别（会客室 → 干员经验 → 武器经验 → 培养）。
6. **同分**：只比两级 —— 占用人数更少者胜；人数相同取"先遇到的"（见 `docs/adr/0002-flatten-tie-breaking.md`）。
7. **补位**：白板挑人按"牺牲顺序 + `charId`"只是**基准序**；"烧掉谁"是候选维度（补位变体，预算 4 个）。

### 5.0 算法不判最优

```text
工具（tools/scheduler.mjs → solveLayout）只做两件事：
  ① 在当前候选空间里算出最好的一套方案；
  ② 报搜索状态：跑完 / 节点或墙钟耗尽 / 有候选不收敛 / 启用了近似。
它不运行任何最优性验证，也不打印"已证明最优"。
```

> 也就是说：输出的可靠性由**搜索状态**决定，不是由一句结论决定。

### 5.1 已文档化的等价归并与近似（假设台账）

> 规则：条目一旦被证明（有了断言或可对照的上界）就必须删掉，并记到文末「已消除」表里，防止有人又写回去。

#### A1 · 中枢层按 `(uA,uB)` 归并 + 最少有用干员消耗

| 项 | 内容 |
|---|---|
| 是什么 | 同一 `(uA,uB)` 组合只保留一组"占用这些人机会成本最低"的替补；再按"人数不更多且两段 `u` 都不低"做支配剪枝 |
| 为什么保留 | 每个中枢候选都恰好消耗 6 人 ⇒ 集合包含判据退化为"相等"，**不存在合法支配剪枝**，真正起作用的是归并 |
| 影响范围 | **只在中枢层被额外放宽（正中枢是主流形）时才可能影响结论** |
| 失效信号 | 出现"中枢换班/名单明显更优但没被选中"的方案，且产出差异正好落在中枢相关的类别上 |

#### A2 · 同类双舱类别在仍有剩余助力时按无助力估值

| 项 | 内容 |
|---|---|
| 是什么 | 两座同类设施的类别（`--mfg=2干员` / `2武器`）里，若前序类别没把 2 点助力用完，本类别不枚举助力 |
| 为什么保留 | 助力顺序是字典序：会客室优先。常见配置里会客室总会吃满 2 点，本类别拿不到剩余点数 |
| 影响范围 | 只有"会客室用不到助力 + 同类双舱需要助力"的配置才受影响；触发时会打上"按无助力估值"的近似标记 |
| 失效信号 | 构造"无会客室 + 双舱衰减"的账号，方案产出明显低于手算 |

#### A3 · 中枢补位按"牺牲顺序"挑人（优先级升序近似）

| 项 | 内容 |
|---|---|
| 是什么 | 中枢某些班次凑不满 3 名恢复干员时，用"对最低优先级设施才有用"的干员先补位（培养 → 武器舱 → 员舱 → 会客室） |
| 为什么保留 | 补位人选是组合问题，穷举会放大候选；按牺牲顺序取既符合主逻辑 §6.7，又可预测 |
| 影响范围 | 只在"恢复干员不足 6 人"的名单上触发；满编名单的中枢全是恢复干员，不触发 |
| 失效信号 | 恢复干员不足的账号上，中枢补位人选明显不划算（占走了别的设施的主力） |

#### 其它已知的启发式（不是"假设"，但会限制可证性）

| 机制 | 现状 |
|---|---|
| `h` 只保留"闭式最优前 3 + 同分裁决需要的几个"，竞争候选再展开全部 23 个 | 值驱动展开兜底 |
| 类别分支同一占用集只留"占用人数最少"的一条，人数相同取首遇 | 人数相同即等价（ADR 0002），不再做二级比较 |
| 同类双舱 SOS 的组合数上限（400 组合 / 每档 40 条）、展开只扩赢家签名对 + 对换项 | 极端形状下可能欠搜 |
| `rel > 16` 时退化成成对扫描 | 会打近似标记 |

#### 已消除、不要再写回来

| 旧条目 | 为什么删除 |
|---|---|
| `h` 集合不完备 | 已改为"保留集 + 值驱动展开（竞争候选全枚举 23 个 `h`）"，另有定向反例搜索（0 反例） |
| 补位"挑人顺序"影响打平结果 | 已在最终方案上做补位等价替换（白板换字典序更小的 `charId`） |
| 同分裁决缺少决定性尾序 | 现在**不用尾序**：裁决压成两级（人数 → 首遇），见 ADR 0002 |
| 未收敛候选一律当作"未证明" | 已改为"上界仍能威胁最终值才算数"（真实值 ≤ 上界） |
| 减少人数"只在缺人时展开" | 早期版本**根本没实现**减少人数（缺人直接报缺口、整类记 0）。现在候选空间恒含 `1..工位数`，只在"可用 ≥ Σ2×工位数"时按可证支配剪掉 |
| 同类双舱补位池按舱各自检查 | 补位池是**两舱共享**的：现在把补位数当第二维做分层 SOS（只有快路径赢家不可行时才升级），补位不足不会再整类丢弃 |
| 补位（白板）只按 `charId` 贪心挑一个 | 白板对本科目等价、对**下游类别**不等价：现在把"烧掉谁"当候选维度（基准序 + 只换出，预算 4 个变体），不再按名单大小开关 |
| 跨类别"同分换人"的下游连锁（旧 A4） | 根因是**值最优的候选可能排不出来**：①值驱动展开把"两班凑不出两组人"的签名对也拉进候选；②只在"最优值档"里找可实现人选，找不到就 `return []`，整类被悄悄记 0。修法：展开阶段加 `pairRealizable` 过滤 + 按值档从高到低回退 |

## 7. 当前实现边界（一页看完）

**做得到的**：文档模型内的排班（两班/单班、衰减班、减少人数、同类双舱联合分配、会客室助力、多槽培养），
输出布局 + 心情闭环 + 缺口报告，`verifier` 独立复核合法性与产出重算。

**做不到 / 没做的**：

| 项 | 说明 |
|---|---|
| 「全局最优」的数学证明 | 工具只报搜索状态（§5.0），不声称最优 |
| §6.9 练度建议 | 未实现（需要每个技能当前档位作为输入） |
| `fast` 近似模式 | 未实现，当前只有 exact 一种语义 |
| 衰减班长期值的区间界、双舱助力完整估值 | 未做 |
| 比 32 人满编更大的名单 | 未支持；双舱类别 `rel > 16` 会退化成成对扫描并打近似标记 |
| 低级配方物品换算 | 培养舱槽位换算未接 |
