# 帝江号技能分类（按作用域 × 作用效果）

> 数据版本：1.6（数据更新 2026/10/15）｜来源：`data/帝江号数据.json`（`SpaceshipSkillTable` / `SpaceshipCharSkillTable`），与 `documents/帝江号设施与干员.md`、`documents/干员基础信息.md` 同源。
> 覆盖范围：32 名干员 × 2 技能槽 × 2 档位（Lv1/Lv2）= **128 条技能**，每条技能只归入 **1 个分类码**，无重复计数、无遗漏（Σ 各类别 = 128）。

## 1. 分类体系

### 1.1 属性字典

技能按**两个正交维度**分类：`A 作用域`（技能挂在哪个舱室）+ `B/C/D/E 作用效果`（技能产生什么收益）。效果维度与作用域一一绑定，因此每族效果只出现在一个舱室。

| 属性id | 含义 | 取值 |
|---|---|---|
| A 作用域 | 作用到哪个空间 | `A1`总控中枢 / `A2`会客室 / `A3`制造站 / `A4`培养舱 |
| B 心情效果 | 心情的作用效果 | `B1`心情恢复提升 / `B2`心情消耗降低 |
| C 线索效果 | 线索的作用效果 | `C1`线索总效率提升 / `C2[a-g]`线索`a-g`效率提升 |
| D 生产效果 | 生产的作用效果 | `D1`干员素材效率提升 / `D2`武器素材效率提升 |
| E 培养效果 | 培养的作用效果 | `E1`晶植速度提升 / `E2`矿物速度提升 / `E3`菌类速度提升 |

> 口径说明：本表 `A3 制造站` 即数据中的「制造舱」（`roomType=1`）；`A2 会客室` 在数据里对应两个 roomType（`3` 接待/展示、`5` 线索），但干员技能**只挂在 `5`**，故统一记为 A2，不再细分。

### 1.2 编码规则

**分类码 = 作用域码 + `+` + 效果码**，例如 `A1+B1`、`A3+D2`、`A4+E2`。

- 一条技能有且只有一个作用域、一个效果，因此分类码唯一，可当作技能的分类主键。
- 同一天赋的两个档位（Lv1/Lv2）**共享同一分类码**，差异只体现在强度上（见 §1.4）。
- 效果码共 **15 个**（B1/B2、C1、C2a–C2g、D1/D2、E1–E3），理论组合 4 × 15 = 60 种，**实际出现 17 个分类码**——其余组合在数据中不存在（见 §2.3）。

### 1.4 辅助维度（不参与主编码）

主编码只回答「在哪个舱室、干什么」。同一分类码内部还有三个区分点：

| 辅助维度 | 取值 | 说明 |
|---|---|---|
| 强度档位 | Lv1（`α`/`β`）= 低档；Lv2（`β`/`γ`）= 高档 | 每个天赋恰好 2 档，64 个天赋 → 128 条技能 |
| 作用对象 | 全体干员（B1）／舱内干员（B2）／全部线索（C1）／指定线索（C2*）／指定素材（D）／指定质料（E） | 由效果族决定，同族恒定 |
| 叠加规则 | `C2*` 技能描述明示「进驻即生效，同类不可叠加」；B/C1/D/E 未作限制说明 | 排班时为 `C2*` 去重的依据 |

### 2.5 分类结论

1. **作用域决定效果池**：四个舱室的效果族互不交叉——A1 只产心情恢复，A2 只产线索类，A3 只产制造类，A4 只产培养类。给定技能的作用域即可确定其效果族，反之亦然。
2. **B2 是唯一的跨舱室通用效果**：心情消耗降低在 A2/A3/A4 三舱室均有分布（共 30 条），是三舱室排班的公共「润滑剂」；而 B1 心情恢复提升只存在于 A1，且是唯一**全局生效**（作用于所有干员）的类别，与 B2 的**舱内生效**形成互补。
3. **必填类目全覆盖**：线索 a–g 七类均有技能覆盖，无 `C2h` 以上编号；三个培养质料、两类制造素材也都有对应分类码，不存在「某产物无加成」的缺口。
4. **技能条数 = 天赋数 × 2**：每个天赋恰好 2 档位，因此各分类码的条数必为偶数（实际取值 2/4/8/10/12/14/20），条数差异实质反映的是天赋数量与稀有度的分布，R6 干员更倾向进入 D/E/C2 等产出型类别（A2、A3、A4 中 R6 技能分别占 22/20/22 条）。
5. **C1 与 C2 语义不同**：C1 是「收集效率」（对所有线索的产量提速），C2 是「指定线索出现概率」（改变线索产出结构），二者不可互换，也不能把 C2 当作 C1 的子集来加和。

## 5. 易错点与边界

| # | 易错点 | 正确口径 |
|---|---|---|
| 1 | 按序号类推 E 族 | `E1`=晶植（`materialType=2`）、`E2`=矿物（`3`）、`E3`=菌类（`1`）；E 编号与 `materialType`、`roomAttrType` 顺序都不同，必须查表 |
| 2 | 把 C2 当成「效率」 | `C2[a-g]` 实际是**指定线索出现概率提升**（属性 id 里统称「效率提升」），无数值倍率，只有一档/二档；`C1` 才是收集总效率 |
| 3 | 把 A2 细分成两个会客室 | 数据中 `roomType=3`（接待/展示）**无任何干员技能**，全部线索类技能挂在 `roomType=5`，故 A2 只有一个分类码族 |
| 4 | 「制造站」与「制造舱」混用 | 同一实体：属性 id 表中称制造站，`SpaceshipRoomTypeTable` 中称制造舱，`roomType=1` |
| 5 | 忽略全局/舱内差异 | `B1`（A1）作用于**所有干员**；`B2`（A2/A3/A4）只作用于**该舱室内**干员。两者不能直接相加成「心情收益」 |
| 6 | 重复计数 | 128 条技能每条只落一个分类码，Σ 各类别 = 128；不要因「槽」或「档位」再乘一遍 |
| 7 | 同一干员两槽同舱 | 11 名干员两槽同属一个舱室（如洁尔佩塔、骏卫、莱万汀均在制造舱，A3+B2 + A3+D1/D2），排班时二者共用同一工位选择 |
| 8 | 叠加规则 | 仅 `C2*` 明示「同类不可叠加」；其余类别数据未给叠加限制说明，不应自行假设可加或不可加 |

## 6. 复现说明

分类码由 `data/帝江号数据.json` 的 `operators[].shipSkills[]` 逐条按 §1.3 规则打码得到，校验结果：

- 技能总数 128，落码 128，未分类 0；
- 分类码 17 个，无空类别；
- 每条技能的作用域码与 `roomType` 一一对应，效果码与 `effect.type`（及参数 1/2）一一对应；
- 每个分类码内技能数 = 天赋数 × 2（档位数）。

原始数据与既有文档的关系：设施/等级/配方等底座数据见 `documents/帝江号设施类型.md` 与 `documents/帝江号设施与干员.md`；干员逐人技能原文见 `documents/干员基础信息.md`；本文只做**分类视角**的归纳与索引。
